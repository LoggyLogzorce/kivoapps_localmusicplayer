# KivoPlayer

**KivoPlayer** — локальный музыкальный плеер для компьютера, созданный для комфортного воспроизведения собственной музыкальной коллекции.

Плеер ориентирован на локальное хранение музыки, быстрый поиск, визуальное сопровождение воспроизведения и персональные рекомендации. Музыкальная коллекция не требует загрузки в сторонние музыкальные сервисы.

> 🚧 Проект находится в активной разработке.

## Поиск

Поиск в KivoPlayer разработан не как простое сравнение введённой строки с названием трека. Он использует несколько механизмов, которые позволяют находить нужные композиции даже при неточном вводе.

Поиск выполняется по **названию трека и исполнителю**. Для обработки запросов используется **Fuse.js**, настроенный на нечёткое совпадение строк. Это позволяет находить подходящие результаты даже при наличии небольших опечаток или неточного написания.

### Нечёткий поиск

Например, если в коллекции есть:

```text
The Weeknd - Blinding Lights
```

то запрос с небольшой ошибкой вроде:

```text
Bliding Lights
```

может всё равно найти нужный трек.

Для поиска используется отдельный индекс, в котором название и исполнители подготавливаются заранее. Оригинальное значение имеет больший вес, а транслитерированное — дополнительный вес, что позволяет учитывать разные варианты написания.

### Исправление неправильной раскладки

KivoPlayer умеет распознавать ситуацию, когда пользователь начал вводить запрос в неправильной раскладке клавиатуры.

Например:

```text
руддщ
```

вместо:

```text
hello
```

Поисковая система создаёт альтернативный вариант запроса с заменой раскладки и также проверяет его.

Поддерживается преобразование между латинской и кириллической раскладками. При смешанном или неподходящем вводе преобразование не применяется.

### Транслитерация

Поиск также использует транслитерацию. Это позволяет находить композиции, когда пользователь вводит название с использованием другой системы записи.

Например, поисковый запрос может проверяться как в исходном виде, так и в транслитерированном варианте.

При построении поискового индекса для каждого трека подготавливаются оригинальное и транслитерированное представления названия и исполнителей.

### Несколько вариантов одного запроса

Для одного введённого запроса KivoPlayer может сформировать несколько вариантов:

1. исходный запрос;
2. транслитерированный запрос;
3. запрос после смены раскладки;
4. транслитерированный вариант после смены раскладки.

После этого результаты объединяются, а для одинаковых треков сохраняется лучший полученный результат.

Таким образом, пользователь может не задумываться о том, в какой раскладке он вводит запрос и насколько точно написал название композиции.

### Резервный режим

Если библиотека Fuse.js по какой-либо причине недоступна, KivoPlayer использует резервный механизм поиска.

В этом режиме также учитываются исходный запрос, транслитерация и возможная смена раскладки, после чего выполняется прямое сравнение с названием трека и исполнителями.

### Оптимизация

Поисковый индекс не создаётся заново при каждом вводе символа. Данные для поиска подготавливаются заранее, а индекс перестраивается только при необходимости.

Для Fuse.js установлен порог нечёткого совпадения `0.4`, а слишком короткие совпадения длиной менее двух символов игнорируются. Это позволяет избежать большого количества нерелевантных результатов.

## Система рекомендаций

В KivoPlayer разрабатывается система персональных музыкальных рекомендаций.

Её задача — постепенно формировать представление о музыкальных предпочтениях пользователя и использовать эту информацию для подбора подходящих треков из локальной коллекции.

Уже реализована базовая система обратной связи:

* 👍 **лайк** — трек нравится пользователю;
* 👎 **дизлайк** — трек не подходит пользователю.

Эти действия являются основой для дальнейшего развития алгоритма рекомендаций.

Интерфейс системы также предусматривает визуальную обратную связь при оценке трека: анимацию лайка, частиц и других эффектов, чтобы действие ощущалось как часть интерфейса плеера.

Система рекомендаций пока находится в стадии разработки. Алгоритм постепенно расширяется и в дальнейшем может учитывать больше характеристик прослушивания и музыкальной коллекции.

## Обложки и оформление

KivoPlayer извлекает встроенные обложки из музыкальных файлов и использует их не только для отображения текущего трека.

Цветовая палитра обложки может использоваться для формирования динамического акцентного цвета интерфейса.

Благодаря этому оформление плеера изменяется вместе с воспроизводимой композицией.

Если у трека отсутствует обложка, используется стандартное изображение-заглушка.

## Визуализатор

Во время воспроизведения KivoPlayer отображает визуализацию, синхронизированную с аудио.

В интерфейсе используются:

* canvas-визуализатор;
* динамическое свечение;
* wave-анимации;
* дополнительные визуальные эффекты;
* отдельный режим «Волна».

Для устройств с ограниченными ресурсами предусмотрен режим производительности, позволяющий уменьшить количество визуальных эффектов и снизить нагрузку.

## Тексты песен

KivoPlayer поддерживает синхронизированные тексты песен в формате **LRC**.

При наличии LRC-файла текст отображается синхронно с воспроизведением.

Текущая строка выделяется, а интерфейс автоматически перемещается вместе с позицией воспроизведения.

Предусмотрен отдельный режим отображения текста, в котором lyrics занимают большую часть окна приложения.

## Синхронизация

KivoPlayer предусматривает синхронизацию музыкальной коллекции между устройствами через отдельный сервер.

Клиент может проверить состояние файла на сервере и в зависимости от результата:

1. загрузить отсутствующий файл на сервер;
2. скачать отсутствующий локальный файл;
3. проверить наличие текста песни;
4. загрузить или скачать LRC-файл.

Для идентификации используются fingerprint аудиофайла и fingerprint текста.

Система синхронизации реализуется как отдельный серверный проект.

## Производительность

KivoPlayer рассчитан на работу с большими локальными музыкальными коллекциями.

Для уменьшения нагрузки на интерфейс используются оптимизации отображения списка треков, в том числе виртуализированный список и кэширование обложек.

Это позволяет не создавать одновременно большое количество DOM-элементов для всей музыкальной коллекции.

Также предусмотрен отдельный режим производительности, отключающий или уменьшающий часть визуальных эффектов.

## Технологии

### Desktop

* **Electron**
* **JavaScript**
* **HTML**
* **CSS**

### Используемые библиотеки и API

* **jsmediatags** — чтение метаданных аудиофайлов;
* **Fuse.js** — нечёткий поиск;
* **Color Thief** — получение цветовой палитры из обложек;
* **Web Audio API** — работа с аудио и визуализацией;
* **Electron IPC** — взаимодействие между renderer и main process.

Electron-приложение использует отдельный `preload.js`, Context Isolation и отключённый Node.js Integration для renderer-процесса.

```bash
cd kivoapps_localmusicplayer
```

```bash
npm install
```


В текущей версии запуск приложения выполняется через Electron с помощью `npm start`.
